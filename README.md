# duke1_recon

Historical matching reconstruction of the original 1991 DOS **Duke Nukem**
("Duke Nukum" v2.0), episodes 1–3 (`DN1.EXE`, `DN2.EXE`, `DN3.EXE`), treated as
three historical builds of one logical program.

The working rule is:

> original binary → independent evidence → historically compiled candidate → exact proof → canonical source

Nothing in this repository counts an original byte as source. Original game
files and anything derived from them (unpacked images, objects, executables)
are ignored by git and never redistributed.

## Status

**The reconstruction is complete:** the sources in `src/`, compiled with Turbo C 2.0,
assembled with TASM 1.0, linked with TLINK 2.0 against the stock CL.LIB and packed
with LZEXE 0.91, produce DN1.EXE, DN2.EXE and DN3.EXE byte for byte
(`python tools/link.py --repack`; re-checked by `python tools/validate.py`).

See [docs/progress.md](docs/progress.md) (regenerated by `tools/validate.py --write-progress`)
and [docs/proof-model.md](docs/proof-model.md) for exactly what is and is not proven.
The end state, a readable source tree that builds the three original executables
standalone with the historical toolchain, and the path to it are in
[docs/roadmap.md](docs/roadmap.md).

* **Oracles locked:** all three LZEXE 0.91 executables are hashed, unpacked by an
  independent decoder, and cross-checked by *executing each file's own LZEXE stub*
  in an x86 emulator at two load segments (`tools/oracle.py --crosscheck`).
* **Toolchain identified with discriminating evidence:** Turbo C 2.0, large model,
  `-ml -Z -G -O -1- -f- -K`; `-O`, `-K`, `-G` and `-1-` are each falsified when
  changed, and `-Z` breaks 68 of 170 accepted functions when removed
  ([evidence/compiler-rules.json](evidence/compiler-rules.json), `tools/probe.py`).
* **Census:** every code byte is accounted for as C0L startup (457 B), shared
  hand-written assembly (1,082 B, identical in all episodes), two first-party C
  translation units (G1: 149 functions, 65,393 B, structurally identical in all
  episodes; G2: 99 functions, 18–18.1 KB), 65 CL.LIB modules (12,849 B) and
  2–5 bytes of TLINK alignment fill.
* **Atlas:** 257 logical functions mapped across episodes with separate byte,
  shape, size, call-graph, data-map and order evidence (`evidence/atlas.json`);
  one function that moved within G2 in DN3 is recognised as the same function.
* **Accepted functions:** 7 supervisor pilots plus worker-recovered functions from three
  measured GPT-6 Luna waves (4, 8 and 12 workers), every one proven EQUAL in all three
  episodes and re-proven fresh by `tools/validate.py` ([docs/waves.md](docs/waves.md)).

## Requirements

* Windows, Python 3.11 with `capstone` 5.0.9 and `unicorn` 2.1.4 installed for the
  supervisor; `python tools/setup_env.py` vendors them into `build/python`, which all
  tools (and sandboxed workers) use.
* Pinned tools outside the repo (hashes in [layout/toolchain.json](layout/toolchain.json)):
  `C:\tools\turboc-2.00-full` (TCC/TLINK 2.0, CL.LIB, C0L.OBJ, headers, startup sources, TASM 1.0),
  `C:\tools\nmlgcdos\msdos.exe` (MS-DOS Player), `C:\tools\dosbox-x` (independent runner).
* The original v2.0 files in `assets/` (or `$DUKE1_ASSET_DIR`).

## Rebuild from a clean clone

```bash
python tools/setup_env.py
python tools/oracle.py --crosscheck
python tools/census.py
python tools/atlas.py --check
python tools/tu.py --check
python tools/db.py rebuild
python tools/probe.py
python tools/validate.py --tests
```

`build/` (oracle materialisation, census, compile cache, worker scratch) and
`state/research.sqlite` are disposable; every accepted proof is re-derived from
`src/`, `recipes/`, `layout/` and `evidence/`.

## Everyday workflow

```bash
python tools/context.py g1_0042                    # what is this function?
python tools/context.py g1_0042 --skeleton > build/workers/me/cand.c
python tools/search.py build/workers/me/cand.c --function g1_0042 [--asm]
python tools/promote.py g1_0042 build/workers/me/cand.c --verify-only
python tools/promote.py g1_0042 build/workers/me/cand.c   # supervisor only
python tools/validate.py
```

Parallel workers: [AGENTS.md](AGENTS.md) and [docs/workflow.md](docs/workflow.md).

## Layout

| Path | Committed | Contents |
|---|---|---|
| `tools/` | yes | oracle, census, atlas, compiler wrapper, strict comparer, promotion, validation, tasks |
| `layout/` | yes | oracle lock, toolchain pins, compiler profiles, symbol aliases |
| `evidence/` | yes | atlas, compiler rule register, promotion log, curated blockers |
| `src/g1`, `src/g2` | yes | accepted function sources (one file per logical function) |
| `recipes/` | yes | per-function proof recipes (profile, per-episode extents and hashes) |
| `probes/` | yes | object-level compiler probes |
| `tests/` | yes | unit and safety tests |
| `docs/` | yes | proof model, compiler profile, oracle notes, workflow, porting notes |
| `assets/`, `build/`, `state/` | **no** | originals, regenerable artefacts, research database |
